## 2. 範圍與既有功能

滿版指填滿瀏覽器可用視窗，本版不增加系統全螢幕要求。沿用現有 Svelte 5、Vite 與 three.js，不預設增加動畫或捲動套件。

保留三地模型、低空路徑、日夜循環、11 種屬性天氣、卡牌傾斜與放大、捕捉機率及動畫、我的圖鑑資料、中英文搜尋、卡種篩選與 iOS 傾斜授權。單純把卡牌換到中央不觸發天氣，仍由點擊放大切換，收合後保留；到站浮現不修改日夜或屬性天氣。

遵守全部凍結區、繁體中文用語、Vite base `/` 與 `.env.local` 不提交的約束。新元件使用 runes。現有卡牌資料、每區切片及卡種順序作為規劃基準，不另行刪減、重排或改寫。既有 `pokedex.v1` 保持可讀。

重製範圍為頁面骨架、導覽、卡牌外層排列與旅程協調。角色行走、自由探索、戰鬥、任務、站點解鎖、額外音效及自動切換屬性天氣均不列入本版。

## 4. 開場與載入

1. 最初以輕量 HTML/CSS 顯示天空色底、站名、精靈球符號與「正在前往真新鎮…」，不必等 three.js 下載才出現。
2. 等場景完成初始化及首次有效渲染後，淡出載入提示。優先準備卡牌資料與首站圖片，其餘圖片延後載入；不等待全部 18 站圖片。
3. 自動從略高的俯視構圖下降並向前推進，同時調整注視方向，接到既有路徑起點。暫以 1.5–2 秒為原型時長，不能露出地景邊界或穿過屋頂、雲團。
4. 操作入口與「向下捲動，開始旅程」提示淡入，鏡頭控制交給旅程。

實作基準：不顯示虛構百分比或為動畫強制延長下載等待；提供略過開場。開場中明確的捲動／導航操作可提前結束下降，從合法旅程位置接續，不累積輸入後突然衝到遠處。

一般從頁首載入時自動播放；由有效卡種網址錨點、瀏覽器歷史或已恢復的旅程位置進入時，直接恢復目的地。開啟／關閉面板與回到起點不重播下降。重訪紀錄僅限當次頁面生命週期，不寫入圖鑑或永久儲存。

新版取消舊式獨立 Hero 卡牌區，保留站名與「卡牌效果 by simeydotme」連結於開場標題區，README 保留完整授權與致謝。舊 `cards[0]` 不再是開場必須渲染的展示卡；此為本版版型基準，不變更凍結資料。

下載慢時維持真實載入提示；場景初始化失敗／WebGL 不可用時進入靜態背景版本，卡牌資料失敗則提供明確錯誤與重試。首站單張圖片失敗僅影響該張，不能造成整站永遠 loading。場景就緒與卡牌資料就緒需各自處理。

## 5. 18 站與捲動節奏

站序沿用：普通與非普通 → 反閃卡 → 閃卡 → 宇宙閃卡 → 驚奇稀有 → 光輝寶可夢 → 訓練家畫廊閃卡 → 寶可夢 V → 寶可夢 V 全圖 → 寶可夢 V 異圖 → VMAX → VMAX 異圖 → VSTAR → 訓練家全圖 → 彩虹稀有 → 黃金秘密稀有 → 訓練家畫廊 V 與 VMAX → 閃色寶藏。

每站以既有 section id 為穩定識別，另設定路徑位置、所在地名稱、移動距離及停留距離。三地各有幾站不預設平均分配，以沿路構圖決定。

第一階段先在既有路徑進度 0.04–0.96 間等距放置 18 個候選點，再依真新鎮、一號道路、常磐市的可見地標調整。站序及路徑位置始終單調遞增；所在地依實際鏡頭位置校正。原型可先取第 1、9、18 站，驗證長距離跳站及三地景觀。

每站分為移動、入站、停留、離站：移動區間推進鏡頭，停留區間讓鏡頭位置不變；前後退場銜接地景。初始捲動距離可取移動約 0.6 個視窗高度、展示約 1.2 個視窗高度，再依真實滾輪／觸控板／手機感受調整。這些數值是調校起點，不是固定驗收答案。

反向捲動沿原路返回。快速跨站只呈現目前目的地，不排隊補播中途演出；鏡頭與展示狀態使用同一進度，平滑延遲不能使卡種已更新而鏡頭仍停在上一地點。實作採約 90ms 時常的共同平滑跟隨；輸入一次跨越超過一站距離時直接同步目的地，不逐站追趕。最後一站後保持旅程終點，可由地圖返回任一站，不自動循環。

網址錨點與圖鑑跳站皆落在目標站穩定停留區的中間，避免落在進出邊界。地圖遠距離跳站採短暫淡出／淡入直接抵達，不快速飛越所有中間站；正常旅程仍保持連續飛行。

## 6. 遭遇、重訪與換卡

首次抵達：鏡頭進入停靠範圍 → 卡種名稱 → 中央卡牌、左右預覽與博士對話輕快浮現。依實作回饋取消地景壓暗與光圈；首次穩定約 100ms 後、重訪約 60ms 後顯示內容，以約 280ms 淡入與 9px 上移帶出。減少動態時立即呈現。

同次瀏覽每站首次完整顯示卡牌後才記為已到訪；演出中已離開且未看到卡牌的站不記入。回頭或地圖重訪採簡短轉場，保留各站上次選到的卡牌。重訪博士直接顯示全文；首次沿用逐字、點擊顯示全文的既有規則。

動畫可中斷，離站立即取消舊站的演出與逐字程序；臨界位置使用穩定的入／離站判斷，避免微小捲動反覆閃動。沒有「演出結束才能繼續」的鎖定。減少動態時直接顯示內容。

換卡提供左右按鈕；焦點在輪播內時支援左右鍵，手機支援水平滑動，垂直手勢留給旅程。首尾不循環、邊界按鈕停用，沿用現有輪播習慣。點左右預覽先移到中央，再點中央進入放大；滑動結束不可誤觸放大。

放大期間暫停旅程與輪播切換，保留卡牌傾斜、捕捉及收合規則；收合後恢復該站與原本選取。放大未收合前不卸載其元件，外層不可裁切閃卡、放大卡牌或捕捉演出。

## 7. 面板、導航與狀態

以旅程狀態加上獨立的面板／放大狀態協調，避免把「搜尋面板內正在放大卡牌」錯當成已退出搜尋。

| 情境 | 行為基準 |
|---|---|
| 打開地圖／搜尋／圖鑑 | 暫停旅程位置與鏡頭視差，面板自身可捲動；地景日夜及天氣保留 |
| 關閉面板 | 恢復原站、換卡位置及開啟入口的鍵盤焦點 |
| 切換工具 | 同時只開一個主要面板；保留搜尋文字、結果與其捲動位置 |
| 搜尋卡牌放大 | 視窗層級完整檢視，捕捉仍可用；收合回搜尋結果 |
| 圖鑑點選有展示區的卡牌 | 前往該站並選中目標卡牌，使用同一導航入口 |
| 圖鑑點選外部搜尋卡牌 | 打開搜尋面板並沿用名稱查詢 |
| Escape | 先關閉最上層放大檢視，再關閉面板；一次只退一層 |
| 載入有效卡種錨點 | 略過起點開場，資料就緒後抵達該站 |
| 瀏覽器上一頁／下一頁 | 恢復對應導航位置，不觸發新的重複歷史記錄 |
| 單純切換日夜 | 不移動旅程、不重播遭遇 |

一般捲動不逐幀新增歷史紀錄；明確跳站與錨點導航由同一控制入口維護網址。面板開關需保存／恢復捲動位置，不使背景在解鎖時跳動。

## 8. 技術拆分與實作路徑

目前 `town.js` 的 `measureJourney()` 讀取 `main .section` 的 DOM 位置，交由 `progressFromSections()` 推算鏡頭進度；`App.svelte` 以長頁面掛載 18 區，搜尋時替換主內容。滿版重製需調整此耦合。

建議以固定高度的旅程捲動容器提供原生捲動距離，滿版舞台與 3D 場景依共同旅程狀態更新；卡牌圖片及對話長度不參與旅程距離計算。繼續沿用 `sampleFlight()` 的地景路徑取樣，新增開場相機與旅程相機的交接。

| 模組／檔案 | 規劃責任 |
|---|---|
| `src/config/journeyStops.js`（新增） | section id、路徑位置、所在地、移動／停留距離；引用既有卡種設定 |
| `src/journey/timeline.js`（新增） | 純計算：捲動位置與停靠狀態、路徑進度、指定站落點互換 |
| `src/stores/journey.svelte.js`（新增） | 旅程位置、開場狀態、已到訪、每站換卡位置與暫停原因 |
| `src/App.svelte` | 組裝滿版舞台、場景、捲動容器、面板與卡牌狀態 |
| 新的舞台／遭遇／地圖／載入元件 | UI 呈現與輸入，把跳站交給共用導航入口 |
| `CardGrid.svelte` 或新的輪播外層 | 桌機及手機中央聚焦、左右預覽；複用凍結卡牌元件 |
| `TownScene.svelte`、`town.js`、`journey.js` | 場景就緒訊號、共用旅程進度、開場下降、暫停／恢復 |
| `TopBar`、`Hero`、`Signpost`、`Section` | 用新版入口、開場與舞台取代舊頁面結構；確認無引用後才移除舊元件 |
| 搜尋、圖鑑、博士、捕捉元件 | 複用既有資料與互動，調整顯示容器及焦點銜接 |
| `app.css`、`index.html` | 全站畫面配置、載入外觀、堆疊及安全區，保留授權與凍結 CSS 引用 |

核心架構另記 ADR-0004，已經第一階段與完整旅程驗證，狀態為 accepted。新檔名為責任切分提案，實作可依既有結構微調。場景相關檔已有使用者未提交修改，實作前逐一核對差異，不覆蓋現有地景與天氣成果。

## 9. 手機、無障礙與效能基準

- 使用瀏覽器可用高度及安全區配置，工具列開合、視窗縮放與旋轉後維持目前站與站內相對進度，不按舊像素位置跳到別站。
- 所有按鈕至少 44×44；可用鍵盤完成換卡、地圖跳站、搜尋、捕捉與返回。面板有可見關閉入口、對應標籤、焦點管理及背景不可操作狀態。
- 減少動態：略過下降、到站浮現與位移動畫，立即顯示卡牌；沿用目前真新鎮靜態鏡頭，18 站仍可用捲動或地圖瀏覽。卡牌名稱與說明不依賴動畫才能讀取。
- WebGL 不可用或初始化失敗：靜態天空背景，保留 18 站、搜尋與圖鑑，不能卡在載入畫面。
- 保留既有低效能場景、天氣減量與分頁隱藏暫停規則。面板開啟可保留環境緩動，鏡頭不跟隨背景捲動。
- 舞台只掛載當前所需卡牌及必要相鄰預覽，換卡位置獨立儲存；預載下一站圖片，不一次啟用 18 站所有閃卡。搜尋及放大檢視另有自己的生命週期。
- 不為到站 UI 另建 three.js 場景，沿用既有場景繪製物件上限檢查。避免逐幀讀取全部卡牌幾何尺寸與新增持續工作的多重動畫迴圈。
- 第一階段記錄同機、同尺寸、同天氣的原版幀時間基準。完整版本以桌機接近 60 fps、手機至少 30 fps 為初始目標，另記錄低幀、長任務與實機條件；不把桌機手機尺寸模擬當成實機驗收。

## 11. 驗收清單

以下保留為驗收要求；實際已執行項目與限制見 [UI 重製驗證記錄](./UI-REMAKE-QA.md)。

1. 冷載入、快取載入、慢網路、圖片失敗、場景初始化失敗皆可完成進站或明確重試；無假進度與永久等待。
