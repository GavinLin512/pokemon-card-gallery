# UI 重製驗證記錄

日期：2026-09-08。P1–P3 已實作；P4 已完成下列程式與瀏覽器驗證，實機項目仍保留待驗收。

## 最終體驗

- 18 站沿既有路徑 0.04–0.96 排列，所在地依既有三地分界為真新鎮 5 站、一號道路 10 站、常磐市 3 站。每站移動 0.6、停留 1.2 個視窗高度。
- 原生捲動輸入以約 90ms 時常平滑跟隨，鏡頭與舞台共同取樣；一次超過一站距離直接同步目的地。停止輸入後收斂且不越過目標。
- 使用者在實作中要求「更流暢 smooth，抵達每站改為輕快浮現」。已取消壓暗及光圈，改為首次約 100ms／重訪約 60ms 後顯示，再以 280ms 淡入及 9px 輕微上移呈現。浮現完成才記到訪；提前離站取消記錄。
- 輪播只掛載一張凍結互動卡牌與最多兩張預覽圖片。每站選卡獨立記憶；搜尋放大有獨立視窗層級，保留搜尋面板狀態。
- 初次場景有效繪製後交接 1.8 秒下降開場。導航、明確捲動、略過與有效錨點可結束／跳過；減少動態保留既有真新鎮靜態相機。

## 幀時間樣本與限制

| 環境 | 中位數 | P95 | 其他 |
|---|---|---|---|
| 修改前 Aside，1716×1156，清晨、原景、旅程起點，120 幀 | 16.7ms | 17.7ms | 同一台開發機的原版基準 |
| 新版 headless Chrome，1716×1156，清晨、原景、首站，180 幀 | 16.7ms | 16.7ms | 0 幀超過 33.4ms，取樣區間無長任務 |
| 新版 headless Chrome，390×844 低效能設定，清晨、原景、首站，180 幀 | 16.7ms | 16.8ms | 0 幀超過 33.4ms，取樣區間無長任務 |

新版與原版使用不同瀏覽器執行模式及旅程位置，不能據此聲稱效能提升百分比。這些是同一台桌機上短時間的 `requestAnimationFrame` 間隔樣本，不能代替手機 GPU、觸控板手感或長時間穩定度。

仍待：至少一台手機實機、iOS 感應授權、真實軟鍵盤／工具列伸縮與長時間強天氣效能；完整慢網路下載與所有 18 站的逐站人工構圖校準。沒有將手機尺寸模擬算作實機驗收。
